# segacd-dc — эмулятор Sega CD / Mega-CD на Dreamcast

[English version](README.md)

Начинался как отдельная программа для Snatcher (USA) и настроен под неё,
но запускает и другие диски Sega CD (см. «Другие игры Sega CD»). Ядро — эмулятор Mega Drive / Mega CD
из PicoDrive (irixxxx/picodrive), работает настоящий BIOS Sega CD. Оба
процессора 68000 — ассемблерный FAME SH4, Z80 — CZ80. Картинку рисует
видеочип Dreamcast: тайлы как прямоугольники, как в md-dc. Продолжение
`snatcher.elf` из dc-poker, но с другой работой с диском: эмуляция никогда
не ждёт привод Dreamcast.

## Сборка

Нужна настроенная KallistiOS (`environ.sh`).

    make            # segacd.elf, с отладочным выводом (perf каждые 2 с)
    make RELEASE=1  # без вывода в консоль
    make SOFT=1     # картинка только программным рендером PicoDrive (для сравнения)

При переключении между RELEASE / SOFT и обычной сборкой — `make clean`.

## Диск

Образ (CUE + BIN со всеми 21 дорожкой) переводится утилитой
`tools/ngcdconv` (та же, что в dc-poker: уже сконвертированный диск
подходит как есть):

    cc -O2 -o ngcdconv tools/ngcdconv/ngcdconv.c
    ngcdconv "Snatcher (USA).cue" out

| Файл | Откуда | Размер |
|---|---|---|
| `1ST_READ.BIN` | `segacd.elf` (scramble) | |
| `BIOS.BIN` или `BIOS_U.BIN` / `BIOS_J.BIN` / `BIOS_E.BIN` | BIOS Sega CD / Mega-CD региона диска: `bios_CD_U.bin` для американского диска (Snatcher), `bios_CD_J.bin` для японского | 128 КБ |
| `DISC.CUE`, `DATA.ISO`, `TRK02.NGA` … `TRK21.NGA` | из `ngcdconv` | 115 + 112 МБ |

### BIOS и регион диска

BIOS загружает только диски своего региона: в начале диска записан код
защиты, у Японии, США и Европы он разный. Японский диск с американским
BIOS заканчивается CD-плеером BIOS. Поэтому эмулятор берёт BIOS по региону
диска (из его заголовка): `BIOS_J.BIN`, `BIOS_U.BIN` или `BIOS_E.BIN`, а
если такого нет — `BIOS.BIN` (все файлы — в корне диска).
Если регион BIOS (буква в его заголовке) не совпадает с диском, на экране
пишется, какой BIOS нужен.

### Другие игры Sega CD

Эмулятор не привязан к Snatcher: диск любой игры переводится тем же
`ngcdconv`. Проверено (сборка для ПК и SH4-код под qemu, на приставке ещё
нет):

| Игра | BIOS | Результат |
|---|---|---|
| Captain Tsubasa (Japan) | Mega-CD 1.01 J (`BIOS_J.BIN`) | грузится за ~8 с, меню, выбор команды, матчи, заставки; случайный игрок 2 × 60 тыс. кадров без зависаний. Кадр на SH4 в матче ~3,1 млн инструкций (≈15 мс из 16,7: FM-музыка 1 млн), возможны редкие пропуски кадров |

Только для Snatcher: «парковка» подпроцессора в циклах ожидания
(`mcd_idle.c`) — в других играх она просто не срабатывает.

## Управление

| Dreamcast | Sega CD | Snatcher |
|---|---|---|
| A | C | выбор |
| B | B | отмена |
| X, Y | A | бластер |
| Start | Start | пауза / меню |
| крестовина, стик | крестовина | |
| B при включении | | BIOS как есть (CD-плеер, менеджер памяти) |
| Start+A+B+X+Y | | выход |

Сохранения (8 КБ памяти Sega CD) пишутся на первую VMU, файл `SCDBRAM`,
через ~2 с после изменения.

## Почему не должно быть зависаний

**Диск.** На Sega CD игра сначала даёт приводу команду «играть с сектора N»,
и привод какое-то время ищет (PicoDrive считает ~11 тиков по 1/75 с плюс
расстояние). В segacd-dc в этот момент поток (`src/scd/cd_cache.c`)
сразу начинает читать с GD-ROM нужный кусок дорожки данных (64 КБ) и два
следующих. Если сектор, который привод должен выдать, ещё не прочитан,
эмулируемый привод держит его один тик — как если бы поиск был чуть
дольше (`CD_DATA_HOOK` в `pico/cd/cdd.c`). Сама машина при этом не стоит:
процессоры, картинка, звук и музыка идут дальше. В старом `snatcher.elf`
при переходе на другое место диска поток эмуляции сам ждал GD-ROM — это
и были подвисания со сбоем звука на подгрузках.

CD-музыку (NGA) читает второй поток в кольцо на 1,3 с. Настоящий привод
Sega CD не может одновременно играть музыку и читать данные, поэтому два
потока не дерутся за GD-ROM.

**Подпроцессор.** Как в dc-poker, подпроцессор в трёх циклах ожидания игры
«паркуется» и просыпается на прерывании (`src/scd/mcd_idle.c`, код
сверяется пословно).

## Как проверено (без Dreamcast)

- `host/` — сборка для ПК (FAME C), `bench/` — SH4-сборка с тем же
  ассемблерным FAME SH4, что на Dreamcast, под qemu-sh4.
- Игрок со случайными нажатиями (`SC_RANDOM`) с детектором зависания
  (картинка не меняется 2 минуты при нажатиях): около 3,5 млн кадров
  (~16 часов игры) на ПК и 0,5 млн на FAME SH4 — ни одного зависания.
  Случайный игрок проходит часть первого акта (штаб, дом Гибсона, завод).
- Медленный привод (`SC_SLOWIO=40 SC_SLOWRND=30`: +0,5 с на каждый поиск
  и 30 % секторов с задержкой) — игра идёт дальше, только загрузки дольше.
- Через кэш (`SC_CACHE=1`, как на Dreamcast): все секторы совпали с
  файлом, ни одного чтения из потока эмуляции, привод придерживался 5–6
  тиков на 400 тыс. кадров (только первые чтения после старта).
- Прямоугольники против программного рендера: 0 расхождений на 60 тыс.
  кадров.
- Скорость (qemu-sh4, кадр игры, звук 22 кГц, картинка прямоугольниками):
  в среднем 0,94 млн инструкций (≈5 мс из 16,7), 99 % кадров ≤ 1,8 млн,
  единичные кадры до 3,8 млн (смена сцены). Программный рендер был бы
  2,2 млн в среднем и до 3,7 в 10 % кадров.

Первая проверка на консоли (лог r1): дорожка данных ни разу не читалась из
потока эмуляции (`sync 0`), привод придерживался только в первые секунды.
Кадр 4–6 мс, в сценах с FM-музыкой 9–12 мс (YM2612 — около 0,7 млн
инструкций кадра), выводится 118–120 кадров из 120.

## Для разработки

    cd host && make
    SC_BOOT=1 SC_FRAMES=60000 SC_RANDOM=1 SC_CACHE=1 ./scdh BIOS.BIN out/DISC.CUE

Переменные — в начале `host/hostscd.c` (`SC_PPM`, `SC_WAV`, `SC_SCRIPT`,
`SC_HW`/`SC_VERIFY`, `SC_SAVE`/`SC_LOAD`, `SC_TRACE`, `SC_IOLOG`,
`SC_NOIDLE`, `SC_SLOWIO`, `SC_SLOWRND`). `bench/`:
`qemu-sh4 -plugin mark.so bench/scdsh4 BIOS.BIN out/DISC.CUE`.

## Изменения в PicoDrive

База — irixxxx/picodrive 8b5e91b (как в dc-poker) плюс:
- точки вызова md-dc: прямоугольники (`MD_MQ`), FAME SH4 (`FAME_PICO`),
  быстрый YM2612 (`MD_FASTFM`);
- из dc-poker: NGA-дорожки в cue, `CD_DATA_HOOK`, `MCD_IDLE_HOOK`,
  граница защиты PRG RAM для FAME SH4, графический ASIC без перечитывания
  состояния;
- новое: привод ждёт сектор (`cd_data_hook_ready`) и сообщает о поиске
  (`cd_data_hook_seek`).

## Лицензия

PicoDrive — некоммерческая лицензия с обязательной публикацией исходников
(`src/pd/COPYING`); эта сборка распространяется на тех же условиях.
FAME — из MAME4ALL для Dreamcast.
